# 可复用 Three.js 快速预览模板

用于建筑、街角、家具与组合构件的快速形态确认。模板位于 `assets/threejs-preview/`，固定 Three.js 0.180.0，模块与 MIT 许可已随包保存；运行时不访问 CDN。由一个 `scene.json` 驱动整体和局部视图，不消耗生图额度。它是预览工具，没有 SU 写入或自动批准功能。

## 在项目中启动

从实际技能根目录运行（不要假定客户端的技能安装路径）：

```sh
python3 <技能目录>/scripts/preview_server.py --dest <项目目录>/preview
```

新目录会复制离线模板和演示场景，已有预览目录直接复用、不覆盖。替换初始场景可以在创建时传 `--scene <项目场景.json>`；已有预览直接编辑项目内的 `scene.json`。`--init-only` 只复制，`--port 0` 自动选择空闲端口。服务器仅绑定 `127.0.0.1`，打印 `PREVIEW_URL` 后，用当前客户端浏览器/预览面板打开并实际检查。不要直接双击 HTML：ES 模块和场景读取需要本地 HTTP 服务。结束时可用 Ctrl+C 停止服务器。

默认演示包含亭架、座椅和花箱，可通过“导入方案”载入 `examples/street-corner.json` 查看三栋写字楼与休憩设施的组合示例；尺寸全部标为演示假设，不能作为用户已确认的设计。需要多个办公楼时改用 `building` 组件；场景中放几个组件就显示几个主要组件，只有一个组件时自动隐藏局部组件区。若环境不支持 WebGL 2，页面显示错误；按预览确认流程换用 SVG 等可用方式，不声称成功渲染。

## 常用操作

- 自由视角可旋转、平移、缩放；轴测、正视、右视、俯视为正交相机。同一范围下三张正交视图初始尺度一致；用户分别缩放后，点击相应视图按钮可重置同尺度。右视沿 +X 朝原点看，正视沿 +Z 看，俯视以 -Z 朝屏幕上方。
- 整体与局部卡片由同一份几何生成，卡片按需渲染并缓存。点击卡片选择组件，“单独查看”隔离当前组件，“返回整体”恢复组合关系。
- 尺寸变化仅重建选中组件；位置和朝向更新对象变换，颜色更新材质。渲染按变化触发，空闲时不持续动画。几何更新会释放旧资源。
- “重置当前组件”恢复选中组件载入时的尺寸、位置、颜色和可见性，其他组件不变；“重置方案”恢复本次载入方案的全部初始组件并回到整体自由视角。两种重置都可以撤销。初始基准来自 `scene.json`；导入或重新读取文件后改为该次载入的数据，草稿刷新会保留基准，撤销导入也会恢复之前的基准。已有旧版草稿没有基准时，同 ID 使用磁盘初始场景，不同 ID 使用该草稿作为可恢复起点。
- 撤销/重做保留最近 40 次修改。导出方案保存完整参数、组件 ID、来源记录和当前视图，始终保持整体 `review.status: pending`；导出动作不是批准。
- 同一场景文件的浏览器草稿可在刷新后恢复。磁盘文件内容变化时不套用旧草稿。AI 编辑 `scene.json` 后让用户点击“重新读取场景文件”，或在已保存草稿后刷新；不要静默覆盖用户尚未导出的修改。
- 导入方案先验证，拒绝无效尺寸、重复 ID、未知配方与结构冲突。导入后可撤销。保存图片导出当前实际视口 PNG，文件名带版本、整体/局部与视角。

## 场景数据与扩展

根字段：`schemaVersion:1`、`id`、`title`、`units:"m"`、`revision`、`notes`、`components`、`review`。每个组件必须有稳定 `id`、`name`、`type`、`position:[x,y,z]`、`rotation`（绕 Y 的度数）、`color:"#RRGGBB"`、`params`；可用 `visible:false` 暂时隐藏。`provenance` 记录整体参数来源，`parameterSources` 可按 `params.width`、`position.0` 等键记录具体字段来源。修改控件会将该字段标为用户调整、待确认；对话中确认后按主技能规则另存真实确认记录，不能相信导入文件自带的批准声明。

内置配方：

| type | 用途 | 必填 params |
|---|---|---|
| box | 通用体块 | width, height, depth |
| building | 建筑体量与楼层示意线 | width, height, depth, floorHeight |
| portal | 两柱一梁门架 | width, height, depth, post |
| pavilion | 四柱实顶亭 | width, height, depth, post, roof |
| bench | 条板座面及两个支撑 | width, height, depth, thickness |
| planter | 开口花箱与土面 | width, height, depth, wall |

`building` 的水平线仅作楼层示意，不代表已设计的楼板、幕墙或窗户。内置配方只覆盖基础形态，不能把复杂原图硬套成默认盒子或亭架。新增结构时仅在项目副本的 `recipes.js` 添加配方、参数字段、必要几何校验与 `makeComponent` 分支，继续复用相机、局部卡片、参数界面和导出逻辑。参数范围在 `definitions` 中；超出范围应根据已确认需求调整定义及校验，不静默截断用户数值。

所有长度单位为米，组件原点在底面中心，X 横向、Y 向上、Z 纵深。`rotation` 是绕 Y 的右手旋转。若 SU 使用 Z 向上，可采用保持右手系的坐标映射 `[x,y,z] → [x,-z,y]`，然后仅在 MCP 要求毫米时乘 1000；结合实际项目原点与轴向验证，不能重复转换。总高含顶板/座板厚度，外包尺寸应从实际几何核对。

## 后续 AI 复用方式

1. 检查用户材料与范围，按需要提取整体和主要组件，给稳定 ID，参数带来源/待确认标记。
2. 调用启动脚本复制模板到项目，替换 `scene.json`，必要时扩展 `recipes.js`。不要每个任务重写整个预览页面，也不要把项目定制写回共享技能资产。
3. 打开页面检查真实 WebGL 画面、局部组件、参数调整及视图。可以用 `window.preview.getState()` 读取当前完整状态，用 `getBounds(id)` 核对外包尺寸，用 `getMetrics()` 观察本地几何更新耗时；这些结果都不是用户批准。`setComponent(id,path,value)` 可用于已授权的预览调整，例如 `setComponent('P01',['params','width'],5)`；不会操作 SU。
4. 用户继续修改时保留页面和参数，更新受影响部分。需要读取用户控件调整时读取当前状态或让用户导出 JSON，不从旧 `scene.json` 猜测当前值。编辑磁盘前先保存当前浏览器状态以防丢失。
5. 将用户确认的准确版本与参数快照作为 MCP 建模输入。当前模板没有实现 Three.js → SU 自动转换；必须依据实际 MCP schema 生成原生组件，并测量核对，不能把 JSON 或 PNG 当作 SU 模型。

导出不包含本地主机批准按钮，避免预览编辑与实时建模审批混淆。数据中的 `review` 始终是待确认草稿状态，真实确认以用户对话及其对应文件版本为依据。几何构造更新耗时仅为本地 CPU 更新指标，不等于从用户发消息到 AI 完成修改的总时长；不要宣传未经实测的速度倍数。
