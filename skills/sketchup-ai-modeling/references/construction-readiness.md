# 从效果复现到便于构造深化的模型

适用于用户要求模型便于施工深化，或反馈接触面、立面分界、收口及连接不清楚的任务。仅要求外观预览时，不自动扩展为全套施工模型。本文来自一次店铺模型复盘，是建模工作指引；不表示 MCP 已实现自动节点设计或施工验收。

## 核心判断

按视觉对象拼装可以得到相似轮廓，却不一定有合理的板件、支撑与安装关系。将两个对象的包围盒间隙调为零，只能说明特定方向的外包范围接近，不能证明实际接触面重合、连接牢固或构造可实施。高面数、丰富材质和命令执行成功也不代表模型适合深化。

先区分交付用途：外观概念模型、构件协调模型、具有已确认做法的节点深化模型。保留用户已确认的外观与尺寸，只补充目标用途需要的构件信息；隐藏结构、板厚、连接件、安装间隙和固定方式不得由效果图直接当作事实。

## 构件与接触关系

- 按实际构件拆分原生群组/组件：板件、框架、饰面、收口、设备及安装部件应能独立定位和修改。重复件复用组件定义；饰面与基层分层，而非只有一个大体块。
- 有体积的板件按已确认厚度建立闭合实体；膜层、示意面等按用途说明，不能要求所有对象一律为实体。相邻独立构件可各自保留接触面，不因此强制合并；清理同一构件内的重复面、意外内面、反面和无意义穿插。
- 每个关键连接记录：两侧构件 ID/原生路径、安装基面、关系类型（贴合、搭接、嵌入、留缝或铰接）、方向、预期距离或深度、容差及参数来源。它是项目说明记录，不是可直接提交给 MCP 的既有 schema。
- 接触检查针对实际边界/面，而非仅对总包围盒。明确接触区域、标高、端部覆盖关系及支撑位置；设计留缝应保留并标注，不要为“消除间隙”把所有接缝焊死。
- 安装链表达完整：例如安装基面—底座/轨道—连接杆—灯体。可见吊杆接上顶面，并不意味着隐藏固定结构已经设计。

## 店铺案例：可迁移的拆解方式

下列对象用于说明检查方法，不是其他项目必须照抄的构造。

| 部位 | 容易出现的问题 | 深化时检查什么 |
|---|---|---|
| 顶部与雨棚 | 大块体相接，底面、顶板、侧封边混为一体 | 分清顶板、吊顶、檐口和侧封板；明确搭接、端部及支撑位置 |
| 门头与立框 | 轮廓连续，转角与饰面分界含糊 | 区分基层与饰面，明确转角谁覆盖谁、在哪里收口 |
| 格栅与格柜 | 顶部仅靠贴齐，没有安装边界 | 顶底收口、柜体边板、端头及与吊顶/地面的连接 |
| 灯具 | 灯体和吊杆存在，安装链不完整 | 安装基面、轨道、底座、转接件、吊杆与灯头的连接 |
| 吧台 | 柜体、饰面、台面互相穿插 | 台面出沿、饰面终点、端板、踢脚及柜体边界 |

先选一个代表节点，例如“雨棚—门头—立柱—灯轨”，把层次和连接理清，再将同类规则应用到其余节点。不要为了统一样式修改无关构件。

## 技术视图与验收

效果视图用来判断材质和整体比例；技术视图用平行投影、清晰轮廓、构件分区和必要尺寸表达安装关系。保留真实折角、接缝和材料分界，只在连续曲面内部平滑细分边；不要用全局平滑隐藏构件边界，也不要靠加粗线条掩盖拓扑问题。

按实际问题选择正立面、侧立面、节点剖面或局部分解视图。日常修改可只检查受影响节点；当连接/遮挡尚未解决时，补充能揭示问题的剖面，不受“日常只抓一张效果图”的优化限制。无需每次遍历全部视角。

验收记录区分：

1. **预期**：已确认的尺寸、连接关系与容差，保留图片推断及缺失项的来源状态。
2. **原生实测**：对象唯一位置、模型修订、测量对象/方法与结果；旋转构件用变换后的实际几何测量，不能把宽松包围盒当精确构件尺寸。
3. **视图证据**：实际检查过的立面、剖面和局部，注明仍不可见或未确定的连接。
4. **未完成项**：材质文字、隐藏做法、安装件或保存/重开尚未验证的部分分别列出，不以离线检查代替原生验收。

自动检查出现对象身份歧义时，先核对组件实例路径与共享定义。不要通过重建同一模型、降低容差标准或改写冻结验收记录制造“通过”；工具检查受阻与几何缺陷分别报告。

## 后续 MCP 能力建议（尚未实现的方向）

优先考虑以稳定构件路径记录接触/安装关系、按实际面报告间隙与穿插、保留硬边和材料分界，以及按问题生成节点剖面。实现前先发现当前 schema 与工具能力；不能把这些建议当作已有工具参数、自动检测或施工认证。

交付称谓应与证据一致：原生可编辑不等于持续参数化；视觉相似不等于节点正确；具备清楚的构件关系仍不替代实际材料、连接做法及专业设计确认。
