# 景观建模

按这次设计范围选择数据：场地边界及已知尺寸、坐标/北向、基准标高、地形点/等高线、出入口与需保留对象、道路与铺装范围、种植需求、水体与构筑物。已有明确尺寸优先于图像预测。没有高程资料时不要把平面色块自动解释成地形；可提出平场或具体高差供用户确认。

## 构件组织

用稳定逻辑 ID 划分地形、园路、铺装、水体、构筑物和种植；每个对象记录来源与参数。名称便于阅读，persistent ID/返回的实体路径负责可靠定位。现状保留对象和新建对象分别管理，不覆盖现状模型。

地形使用明确的边界和采样点；细分密度由成果比例和曲率决定，限制面数。园路记录中心线/边界、宽度、标高和曲线分段策略；如只支持离散折线，报告近似和误差。台阶、坡道、挡墙与场地接触处优先检查断层、穿插和悬空。

植物使用可重复组件与确定的排列/随机种子；先明确树种/外形代理、冠幅、株距、数量与需要排除的区域。用低复杂度代理验证空间，确认位置后再替换详细资产。可见造型不能证明适地适树或养护可行，未经专门核查不输出此类结论。

## 分阶段流程

1. 确认缺失高程、路宽、构筑物尺寸及所有预测值；得到明确确认后构建边界、地形/平场、主路和主建筑白模。
2. 检查坐标、范围、关键断面、出入口衔接和净空；调整时保持已确认参数及对象身份。
3. 增加次路、铺装、台阶/挡墙、水体、小品、种植，再加入传统材质或运行时支持的外观。
4. 从俯视和至少一个能看清高差的视角检查；测量路径宽度、主要标高、对象间距与数量。面积统计须注明测的是水平投影还是表面面积。

坡度、路宽、踏步和排水值属于具体设计输入。若提出建议值，说明用途与假设并请用户确认；不能把本工具的范围校验或碰撞检查称为无障碍、道路或结构合规审查。

## 与当前 MCP 的关系

先用 `get_docs(topic:"dsl")` / `get_capabilities` 查到受支持的操作。例如当前 DSL 可能提供 `terrain_mesh`、`path_surface`、`stairs`、`railing` 等，应按实际 schema 组合；本技能不提供一个额外的 `landscape` task 类型，也不保证每一项复杂构造都已实现。

若操作被标为 partial 或返回几何失败，缩小到具体对象、保存已有结果并说明缺少的能力。不能以图片纹理替代用户要求的地形、洞口或可编辑构造，却报告它们已建成。
