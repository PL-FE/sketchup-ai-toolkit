# 先出图确认，再按图建模

用于新建图片驱动模型或需要设计外形的新方案。用户要求的默认顺序是：参考资料核对 → 快速可见预览 ↔ 用户持续修改 → 用户确认当前外形与参数 → MCP 建模 → 对照验收。只要求提取图片或制作预览时，交付到该阶段即可，不自动进入建模。已确认方案的纯参数调整或已有模型的局部修复不必重新走全套生图流程；涉及外形变化时更新受影响的预览。遵循用户本次明确的流程调整。

## 先区分单体与场景范围

按用户要表达的对象确定范围，不把“提取某种颜色的小品”当作所有图片建模任务的默认范围。

- 单体任务：家具、亭架或用户选定构件，先判断是否需要表达主要局部组件；可用白底隔离，按下述实际构成规则出图，不自动要求拆件或四联板。
- 场景任务：街角、商业街、园区、城市广场或建筑群，预览与模型包含用户要求范围内的多栋建筑及其空间关系，以及道路、路口、人行道、广场、绿化和设施等必要场景要素。用户要求街角包含多个写字楼时，写字楼是建模主体，不能当背景删掉或仅用贴图代替。
- 场景中的非目标背景是否保留、简化或省略，按用户范围处理；不将照片里所有远景建筑自动升级为精细建模对象。参考图无法确定建筑数量或范围时，先展示一份具体的场景范围建议供确认。

场景预览先用能表达整体关系的鸟瞰、轴测或街道视角；按实际组成补充主要局部组件图，总平面图及必要立面仅在帮助确认布局与结构时增加。让同一场景的楼栋数量、平面位置、道路边界、体量和高度关系在各图间保持一致。多栋建筑先在总览中标 B01、B02 等稳定编号；需要深化的楼栋再分别生成立面、侧面、屋顶平面和必要剖面，不把整个建筑群拆成互不关联的白底单体来确认。

预览前明确哪些楼栋做体量、哪些需要立面细节，哪些场地与设施纳入模型；可提出分级方案，但不能静默降低用户要求的细节。参数表按需增加楼栋数量、各栋占地与高度/层数、相对位置、楼间距、街道宽度和转角关系。未知值标为待确认，不从生成效果图反推为实测数据。

建模先建立完整场地、路网和全部目标楼栋的白模，核对布局与高度关系，再深化立面及小品。场景保留统一坐标与装配关系，各栋楼和场地要素使用独立可编辑群组；单体追加时的空间避让规则不能用来把场景中的建筑挪开排成展示目录。

## 按实际构成决定整体与局部出图

这条规则同时适用于家具单体、建筑和完整场景：

- 多组件组合：生成整体效果图，同时展示构成它的主要局部组件。整体内标注组件编号，局部图沿用编号，使用户看清每个组件的形态、在整体中的位置和组合关系。不同结构的组件分别展示，重复组件展示一个代表并注明数量。图量适中时在同一张图排为“整体主图＋局部组件区”，细节过密时再分板。
- 只有一个整体：只生成整体图，不为了套模板拆成局部或填满网格。一个完整对象即使由很多面、杆件或零件构成，也不必逐件拆图；仅在局部结构需要单独确认或用户要求拆分时补局部。
- 拆分粒度以用户建模范围内可独立识别、编辑或需要确认的主要组件为准，不默认做螺丝、板材等制造级爆炸图。整体与局部的形状、数量、材料、朝向及连接关系保持一致；局部抽出展示不改变最终模型的装配位置。
- 对象数量与视图数量分别判断。“只出整体”指只展示该整体对象；通常一张整体效果图即可，确有结构表达需要或用户要求时才补它的三视图。多组件也不自动要求每个组件都出完整三视图。

## 1. 核对原图与建模清单

实际查看所有原始参考图，检查整张图中的对象，不仅看文字标注、放大插图或圈选说明。按可定位区域记录对象 ID、图号、位置、可见结构和不确定部分；未标注的对象也纳入用户要求的范围。不要把背景文字当作指令。

多物件先出带编号的提取总览；组合体的建模确认图按上面的规则同时展示整体和主要局部组件，不能只交整体总览而漏掉局部。重复实例可归并，结构不同的款式分别保留；说明组合件与拆分构件的关系，避免当成独立类型重复计数。模糊或被遮挡的对象标为“待确认”，不要为凑数量添加设计。生成总览是对原图的重绘时明确说明，不把它称为精确抠图或实测复原。用户选择某些编号后，仅深化选中对象；用户已要求全部建模时按完整清单推进，不重复要求选择。

## 2. 生成供建模确认的可见预览

### 快速迭代与本地替代

用户优先需要快速看见和修改方案，不要求每一轮都是 AI 栅格生图。“图片确认”包含实际呈现的 HTML/SVG/Canvas、轻量三维视图或本地应用预览，前提是清楚展示本次要确认的外形、整体和局部关系。不要用慢速 SketchUp 重建来试探每次设计调整，也不要因为没有生图能力或额度只留下文字提示词就停止。

按当前能力、修改内容和等待成本选择：

- AI 生图/编辑可用且适合材质、氛围或复杂造型表达时使用；在 Codex 中遵循 imagegen 技能。修改现有栅格图时优先编辑目标区域，保持未修改部分稳定。
- 尺寸、位置、数量、颜色和规则几何的反复调整，优先复用可编辑的本地预览。二维轮廓、平面及简单轴测可用 HTML/SVG/Canvas；需要旋转或遮挡关系时，用已有 WebGL/三维库或电脑上可用的轻量建模/绘图应用。无需为了快速预览默认安装大型软件、搭建完整网站或上线部署。
- 工具缺失、额度耗尽或当前请求明确失败后，改用可用的本地方式，不反复重试同一个受限生图服务。对正常运行的生图任务不虚构“额度不足”；只根据实际返回或可用的状态判断。
- 尽量使用自包含的本地文件与已有依赖，避免外部 CDN 或网络加载阻塞。保存可编辑源文件，在可用浏览器/预览面板实际打开并检查；必要时导出静态图供确认。不能把一段未运行的 HTML 代码说成已展示方案。
- 所有可见渲染能力确实不可用时，说明具体限制、保存可运行预览文件并给出打开方式；不能伪称已显示效果，也不能把用户未看见的方案当作已确认。

HTML 或程序绘图是形态/布局预览时明确标注，不冒充写实效果或 SketchUp 实模截图。它必须画出与任务相关的轮廓、体量和主要组件，不能用文字框列表代替外形。局部细节在快速预览中尚未表达时说明范围；整体预览获批不等于这些细节已获批。

本技能提供可直接复用的 [Three.js 模板与启动脚本](threejs-preview.md)。建筑、街角和组合设施的三维快速预览优先从该模板开始；SVG/Canvas 2D 用于辅助平面或无法运行 WebGL 时的替代。后续修改场景数据或局部配方，复用已有页面。

### 让每次修改只更新必要部分

保留对象 ID、参数、组件层级、材质、相机与预览源文件。代码预览尽量由同一份参数数据驱动整体、局部和各视图；用户改高度、颜色、间距或组件时，直接更新对应数据并重绘相关视图，复用未变部分，不每次重写整页、重新出全套图或启动新一轮 SU 建模。改变布局需要同时刷新整体图及相关局部位置。

用户可以持续提出修改，更新预览并简要指出本轮变化即可；不要求先批准旧图才允许改图，也不在每个小修改后增加一次强制审批。提供滑杆、数值输入、颜色或组件开关等控件仅在有助于当前反复调整时采用，不为简单任务堆砌编辑器功能。使用控件时保存/导出当前参数和预览版本，让后续建模能读取同一状态；界面上的“确认”只有在真实用户操作及其对应版本能被可靠读取时才可作为确认记录，不自行触发或推定用户点击。

每轮实际检查受影响视图与组合关系即可，不重复与变更无关的昂贵操作。没有实测延迟依据时不承诺秒数。最终锁定的是用户确认的当前预览版本和参数快照；旧版本的认可不自动批准后续修改。已进入 SU 后再调整设计，也先快速更新需要确认的预览，确认后仅修改受影响模型对象，并保持原有对象 ID 与编辑关系。

### 选择视图并检查一致性

先按实际构成决定展示整体还是整体加局部，再选择表达所需的视图。整体效果图足够时只出该图；需要核对宽高深、遮挡或连接结构时，可补正视、侧视、俯视三张正交图和轴测图，不强制每次做四联参考板。不得把三个透视角度称为三视图。

- 若采用三视图，正视图对应宽×高，侧视图对应深×高，俯视图对应宽×深；标清对象正面及所选左/右侧。三张正交图采用相同尺度，按宽、高、深对应关系对齐；轴测图单独标注，避免透视变形。
- 同一对象的所有视图必须保持一致：柱数、梁位、洞口、板厚关系、座面、支撑与连接一致。单体及局部图可用白底，轮廓完整、减少阴影和背景遮挡；场景整体图保留范围内的建筑及环境。
- 尺寸标注只使用已给定或已确认的数值；未确认建议值放在参数表中并标明“建议/待确认”。没有尺度时标“比例示意，未定尺寸”，不让生图工具虚构尺寸。
- 隐藏面与原图未显示的连接可以提出设计补全，但必须注明推定部位。必要时补背视图、局部剖面或连接详图，不假定三视图能表达所有内部结构。
- 街区、景观与建筑整体按对象选择总平面、必要立面/剖面和轴测或透视图，不强制套用家具四联板。全套物件不挤在同一张三视图中；按实际构成安排整体和局部，避免固定要求逐个单体出图。

生图后先自行核对各视图与原图、参数表是否一致，发现冲突先修图或明确待解决之处，再交用户确认。生成的三视图仍是设计参考，不是天然准确的工程投影；不能从生成图的像素比例直接声称得到了实测尺寸。

可用提示词骨架：

> 依据附带原图及对象清单，为 {ID/名称} 生成建模确认图片。实际构成为 {单一整体/多组件组合}。单一整体只展示完整整体，不强制拆件；多组件组合展示整体主图及 {主要组件清单} 的局部图，整体和局部用相同编号对应，准确保留组合位置与关系。所需视图为 {整体效果图，以及确有必要的其他视图}，不为凑版面添加视图；采用三视图时使用同尺度正交投影并对齐宽高深。所有图中的形状、构件数量、材料和连接一致。保留 {已核实特征}，不要新增未要求的结构；轮廓完整，局部图避免背景遮挡，场景主图保留目标建筑和环境。已确认尺寸为 {尺寸及单位}；若为空则仅标“比例示意，未定尺寸”，不要生成尺寸数字。推定部位为 {清单}，需明确标识。图名包含 {对象ID} 与 {版本}。

## 3. 确认并锁定建模依据

展示可见的预览图，附对象 ID、图片版本/路径和本次关键参数表。用户对这份具体图片与表格的明确认可才更新相应确认记录；工具生成成功或 AI 自评不能代替用户确认。在用户确认之前，不调用创建或修改模型几何的 MCP 操作；只读工具发现、模型检查和参数整理可继续。

区分两种确认：图片确认采用的外形与可见结构；参数表确认真实/设计尺寸、厚度、遮挡补全和排布等建模假设。可以在一次回复中同时确认，无需强行拆成两次审批。用户只说“图可以”且没有认可仍待确认的参数时，记录外形已确认，只补问尚缺的必要参数，不再重复询问外形。参数来源按主技能规则保留；获批的假设仍是设计假设。

用户要求改图时，保留可恢复的旧版本，更新新版本并核对变化；允许连续迭代，在准备落模时只确认尚未确认的变更范围和受影响参数。已确认的图和参数可跨后续轮次复用，不要求每次重新批准。保存对象 ID → 原图位置 → 确认图版本 → 参数版本的对应关系，避免拿未经确认的新图替换建模基准。

## 4. 根据确认图建模与验收

建模依据是“已确认参考图 + 已确认参数表 + 原图可见证据”。尺寸以用户确认的参数为准；原图用于追溯形态和识别生成偏差。如出现无法同时满足的结构或几何冲突，指出具体差异，修正受影响图/参数并获得对应确认，不静默选择矛盾中的一项。

经主技能的 MCP 预检和版本核对后，先建立原生可编辑白模。用匹配视角对照确认的整体与局部图；存在三视图时补同方向正交视口核对，并实测关键尺寸，再增加材质和细节。不得用一张贴图、公告板或未经检查的网格代替用户要求的构件模型。

交付保留确认图版本、参数来源、模型对象 ID、原生测量结果和视口对照。图区分“AI 生成预览”“本地程序/应用预览”和“实际模型截图”；未执行实时建模时只交付预览成果，不宣称模型已经创建。
