# SketchUp AI 建模

目标是可检查、可修改、来源明确的 SketchUp 模型。遵循用户的语言、单位、年份、平台和建模范围。本技能可供 Codex 或其他能读取 Markdown 指令并调用 MCP 的客户端使用；工具前缀、安装目录、界面审批方式由实际客户端决定。

## 开始与路由

先读取 [MCP 调用与恢复](references/mcp-workflow.md)，发现已连接工具和实际 SketchUp 年份。不要假定服务名含 `su2026`，不要因文档出现工具名就认为客户端已连接该工具。没有实时连接时仍可整理参数和预览方案，但不得报告已经在 SketchUp 建模。

按当前材料只读取必要参考：

- 图片、草图、平面图、现场照片：[图片建模](references/image-modeling.md)。
- 场地、地形、园路、种植和景观构筑物：[景观工作流](references/landscape.md)。
- 建筑体量、楼层、墙体、洞口和屋面：[建筑工作流](references/architecture.md)。
- 构造深化、接触面/立面分界或安装衔接问题：[构件连接与深化检查](references/construction-readiness.md)。

## 图片预览确认在建模之前

对于图片驱动的新建模型和需要设计外形的新方案，先按[先出图确认，再按图建模](references/preview-confirmation.md)生成可见预览，获得用户对具体图片和必要参数的确认，再调用 MCP 创建几何。检查整张原图，包含用户范围内未标注的对象。按实际构成出图：多组件组合展示整体效果及主要局部组件，并用编号对应；只有一个整体时只展示整体，不强制拆件。三视图、轴测图及局部详图按结构表达需要选择，不固定视图数量；多视图时核对结构一致性。

预览以快速迭代为优先：用户可持续修改，先更新受影响的整体/局部预览，确认版本后再进入 SketchUp。无生图能力、额度不足或等待成本过高时，按预览流程使用本地 HTML、SVG、Canvas 或可用的轻量三维能力生成可见方案；不得仅交文字提示词后停止。

图片确认与参数确认可以合并进行，但认可外观不等于认可尚未展示的尺寸或隐藏构造。保存确认图版本与对象、参数的对应关系，后续据此建模及对照验收。已确认方案的复用或纯参数修改不重复索取相同确认；本次明确的流程调整以用户指令为准。

用于反复调整建筑和组合设施时，优先复用内置 [Three.js 预览模板](references/threejs-preview.md)，通过 `scripts/preview_server.py` 复制到项目并启动。模板支持离线运行、整体与局部、按需三视图、组件参数调整及 JSON/图片导出；详情和数据约定见该参考。

## 参数确认是建模前条件

**用户要求：图片或资料不足时，先列出关键缺失信息；所有推断、预测或假设的构造参数必须展示给用户，并得到用户针对这份参数表的确认后，才能开始实时建模。** “帮我做出来”“你看着办，直接做”“默认就好”只有在明确指向已展示的具体参数时才是对这些值的确认，不能据此认可尚未列出的构造假设。模型自行填入的 `confirmed`、工具的 `ready_for_modeling` 或握手成功也不构成这种确认。

将参数整理为“名称、值、单位、来源、状态、影响范围”表，并保留用户给出的原始值。区分：

| 来源 | 记录方式 | 可宣称的证据 |
|---|---|---|
| 用户明确给定 | `source:user`，确实来自用户时可 `status:confirmed` | 用户要求；不自动等于现场测量 |
| 原生模型或测量记录实测 | `source:derived`，在 `notes` 记录对象、测量工具/记录、时间或模型修订 | 已测量数值及其来源；设计是否采用仍由用户决定 |
| 图片可见信息 | `source:image`，注明图片与可定位区域 | 可见边界/比例；未经标定不等于真实尺寸 |
| 计算、推断或预测 | `source:derived`，写明输入与公式/推断理由 | 计算结果或预测，不能写成实测 |
| 设计假设 | `source:assumed` | 待确认的设计建议 |

状态使用 `confirmed`、`pending`、`missing`。缺失关键值用 `value:null, status:missing, required:true`；有建议值但未经确认用 `pending`。把确认记录保留在对话和设计说明中，不能自行生成审批凭据。继承本次会话已确认的值，不重复索取同一确认；若尺寸、构造、范围或坐标发生变化，只展示并确认变更及受影响的推导值。

若发现 `preflight_design_brief`，按其实时 schema 提交 brief，利用 `missing`、`needs_confirmation`、`proposed_parameters` 补全表格。它只核对输入，不证明真人批准，不保证原生模型质量。没有该工具时执行同样的人工信息核对并明确这一限制。

缺失信息应具体到能解决建模问题，例如“总平面图上哪一段对应实际多少米”，不要只问“还有要求吗”。可以提出一套明确的概念模型参数供确认，但不能静默补上墙厚、基础、标高、坡度、背面结构或材料厚度。建模容差是本次模型验收尺度，不是结构、消防、无障碍或施工合规证明。

## 建模与编辑

确认项目原点、坐标轴、基准标高及单位。保留原单位显示，并按当前 DSL 的毫米约定转换；明确米到毫米的转换，避免重复转换。指定年份只是目标，实际能力以 live probe 为准；2020 使用可支持的传统材质，不自动调用 PBR/HDR。

先做白模：场地边界/建筑轮廓、主要体量、高度关系、通行与洞口。测量关键尺寸并查看视口后，再增加构件、地形细节、种植、材质与表现；首轮不得用装饰掩盖比例或拓扑错误。不要为了获得空场景清空用户现有模型；在明确的新建范围内使用独立根组。

将业务对象组织为有稳定 ID 的原生群组和组件：一栋楼、一段墙、一条园路、一组植物分别可定位。重复对象复用组件定义。保存原始参数、转换值、参数来源、生成器/配方标识与版本、对象 ID 和父子关系。先核对当前 MCP 支持的 DesignIntent、参数修改或属性操作；有参数基线时沿其修改流程更新，无基线时先建立可审查的编辑方案，不能凭名称或外观推测绑定。

“原生几何可编辑”和“能改参数并重生成”分别验收。只存了一份 JSON 或导入一片网格，不足以宣称已实现持续参数化编辑。若当前适配层不能持久绑定参数，应明确尚缺此能力，交付参数说明与可编辑几何，不伪称参数化流程已经完成。

遵循 `start_agent_task` 返回的 `state` 和 `next_action`。实时调用使用明确的 `runtime:queue`、新鲜连接及稳定幂等键。现有对象修改走服务器提供的审查流程；聊天参数确认不能替代服务器要求的本地主机审查。不要通过自由 Ruby、伪造 token、删除队列文件或改客户端能力绕开限制。

## 验证与交付

对照已确认参数进行原生测量；检查关键外包尺寸、标高、坡度、数量、净空和洞口，区分实测值与由参数算出的期望值。检查法线、意外孔洞/重叠、独立组件、共享定义和对象预算。用俯视、立面/侧视与透视视口核对主要比例、遮挡和连接。离线预检、mock 结果、截图以及“命令执行成功”都不能单独证明完成。

只在用户要求的范围内保存模型，使用独立版本文件并核对保存回执。有支持的磁盘重开流程时按其回执验证；没有执行重开时直接说明。出现超时或未知结果先恢复原任务并检查原生状态，不能换幂等键重做模型或重复关闭文件。

交付包含：模型/保存路径、对应年份、参数与来源表、已执行的测量和视口检查、仍是推测或尚未完成的部分。保留当前 task ID 以便继续编辑；不把概念模型标为施工可用成果。


## 写实级建模与极速迭代准则（Photorealistic Standards & Fast Iteration）

为满足专业建筑/景观效果图级别的写实还原度，并杜绝建模卡顿与长等待，所有 SketchUp AI 建模任务必须严格遵循以下硬性准则：

### 1. 极致写实形体与材质规范（Photorealistic Realism）
- **形态严禁玩具化/卡通化**：严禁使用简单圆柱体直接叠加充当树木（如汉堡包/多层蛋糕树）；
- **树木/植物自然有机生长逻辑**：
  - 树干必须具备自然姿态（微倾、扭曲、S型弯曲骨架、分级主次侧枝与结节）；
  - 树冠采用多尺度自然多面体叶球群落或错落分层叶片，疏密有致，通透透光；
  - 树池内部平铺真实质感的微地形修剪草坪或麦冬灌木丛；
- **现代景观工法节点还原（以高品质景观效果图为基准）**：
  - **双层同心树池体系**：内圈树池挡土墙（带饱满圆润的 Bullnose / 半圆压顶倒角）+ 外圈宽适人体工学休闲坐凳（标高 420~450mm）；
  - **半木半石对比嵌合（Hybrid Wood & Terrazzo）**：半圈嵌入深度炭化防腐实木格栅坐板（四边倒微圆角、端头齐整、阴影通透呼吸缝、预留下沉嵌槽），半圈为整体无缝水磨石/清水混凝土台面；
  - **悬挑踢脚阴影槽**：底座内收 60~100mm，贴地处设置深色收口槽，形成轻盈悬浮阴影；
  - **空间三角化无缝网格（Triangulated Mesh）**：环形回转体、异形双曲面坐凳等空间非共面表面，必须对四边形执行空间三角化（Triangulated Quads to Triangles）并结合 `smooth: "all"`，既 100% 避免 SketchUp 事务回滚，又彻底消除分段棱线黑缝，呈现汽车级无缝流光曲面。

### 2. 极速迭代与性能开销抑制（Performance & In-Place Editing）
- **单图极速预览原则（Single View Only）**：
  - 日常调试、草稿推进与修改过程中，**严禁多角度遍历抓图**，默认只抓取 **1 张** 关键人视效果图；
- **默认禁用阴影（No Shadow by Default）**：
  - 调试阶段默认关闭复杂实时太阳阴影（`shadow.display: false`），将帧渲染与写盘耗时从 20 秒压缩至 1~2 秒；仅在最终整体交付时按用户需求开启高质量阴影与抗锯齿；
- **严禁修改时从零开始（In-Place Mutation over Reset）**：
  - 初次生成必须将场景解耦为独立组件（如 `Comp_Bench`、`Comp_Tree`、`Comp_Plaza`）；
  - 后续修改必须采用**增量就地补丁（Delta Mutation / In-place Edit）**，仅更新受影响的组件、材质或形体参数；
  - 严禁在修改阶段随意调用全盘清空的 `reset_model`，严格保护用户在现场的微调与历史撤销栈。

### 3. 避免 Q 版卡通化：真实市政景观的硬朗工法特征 (Crisp Architectural Form over Soft Blob)
- **警惕过度平滑与“充气甜甜圈感”**：真实大型预制混凝土树池坐凳不是圆滚滚、软趴趴的 Q 版胶囊，而是具备**明确建筑棱角、倒角折线与构造分块**的厚重体量；
- **核心工法断面特征**：
  - **平直内倾斜坡靠背**：靠背是一面坚挺内倾（约 65°~70°）的平整斜坡面板，与水平座面交接处有清晰利落的**阴角折线（Sharp Crease）**；
  - **45° 斜切悬挑下唇（Chiseled Underside Chamfer）**：座面下方通常为利落的倒梯形/斜切收缩面，绝非下垂软弧；
  - **预制分块装配真缝（Control / Expansion Joints）**：大型环形坐凳必须沿圆周设置清晰的**纵向拼装沉降缝（带有真实的凹槽阴影黑线）**，不仅强化工程真实感，更彻底消灭“塑料一体注塑”的玩具感；
  - **宽平座面与精准下沉嵌槽**：座面保持平整坚实，木板条与混凝土交接处有坚挺台口，拒绝含糊过渡。
